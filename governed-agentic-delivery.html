The shift

Move human attention from the diff to the decision

Pipeline

Five verification layers, one feedback loop

Every change passes the same machine layers. The risk score alone decides how much human review it gets.

Attention map

Risk tiers

Human effort rises with risk, not with line count

A deterministic service scores each PR; the highest dimension sets the floor. Most changes should land in T0 and T1.

Comprehension

Engineers stay domain owners without reading every diff

Understanding comes from active work around the change, which is cheaper and sticks longer than passive diff reading.

The knowledge pack per bounded context also grounds the author and reviewer agents, so better human understanding improves agent output too.

Controls

Maker, checker and approver are three separate principals

The maker–checker control auditors already know, applied to agents, with an immutable evidence trail for every change.

Metrics

Measure comprehension next to quality and speed

Quality
  • Escaped defects per tier
  • Change failure rate, MTTR
Verification
  • Reviewer recall on seeded defects
  • Mutation score on changed code
Human load
  • Review minutes per change, by tier
  • Share of changes in T0–T1
Comprehension
  • Teach-back and scenario pass rate
  • People who can explain each context ≥ 2

Every escaped defect ends as a new gate, a reviewer prompt fix or a stricter tier rule, so the system learns instead of asking for more human reading.

Roadmap

Agents earn autonomy through evidence

Nothing reduces human review until the data says it is safe. Set the gate thresholds from your own Phase 1 baseline.
